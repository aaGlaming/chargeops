# Step 1：确认项目范围和验收边界

## 项目范围

- 项目名称：ChargeOps 充电站选址与扩容决策平台。
- 项目目录：`D:/LEARN/AI/programs/AgentTask/Projects/chargeops`。
- 业务对象：区域、充电站、充电连接器、运营商、候选站点、运营指标、故障事件、政策条件和决策方案。
- 主要用户：运营分析师、选址规划师、运维负责人、政策管理员、系统管理员和审计人员。
- 业务闭环：公开数据或业务数据导入 → 站点画像 → 区域/候选点分析 → Agent 运行 → RAG 证据检索 → 评分或方案生成 → 人工确认 → 报告和审计。

## 5 个业务 Agent

| Agent | 独立业务定位 | 主要结果 |
|---|---|---|
| 覆盖缺口 Agent | 判断区域充电设施是否不足 | 区域缺口等级、缺口类型和覆盖指标 |
| 竞争分析 Agent | 分析候选点周边运营商和站点竞争 | 竞争指数、运营商分布和服务空白 |
| 候选选址 Agent | 对候选站点进行多指标评分 | 总分、分项分数、推荐等级和扣分原因 |
| 站点扩容 Agent | 判断已有站点是否需要扩容 | 新增快充/慢充数量、优先级和前置条件 |
| 政策匹配 Agent | 判断候选站点是否符合建设和补贴政策 | 匹配结果、缺失条件、材料清单和截止日期 |

5 个业务 Agent 独立计算、独立运行、独立输出，不把 Supervisor 计入业务 Agent 数量。

## RAG 验收边界

- 文档格式：第一版只接收 Markdown 文档。
- 文档类型：建设规范、电气安全、安装验收、运维手册、故障处理、选址规则、补贴政策、审批要求、扩容规则和报告模板。
- 菜单入口：文档管理、文档上传、文本切块、向量化入库、向量检索、检索结果与原文、RAG 调试。
- 必须实现：上传、解析、清洗、切块预览、切块重生成、Embedding、Chroma 入库、向量检索、关键词检索、元数据过滤、结果排序和原文片段展示。
- Chunk 默认参数：目标长度 800 tokens，重叠长度 120 tokens。
- 检索结果必须保留文档 ID、Chunk ID、版本、来源 URL、生效日期和原文字符位置。
- 每个业务 Agent 必须调用 RAG 检索，并在结果中展示引用的原文片段。
- 无命中或证据不足时，Agent 必须返回证据不足状态，不能补写政策结论。

## MySQL 数据边界

- 公开数据：充电站、连接器、运营商、位置、状态和区域数据，首批使用 AFDC 数据。
- 用户上传数据：候选站点、运营指标、故障记录、预算和交通指标。
- 合成数据：演示用运营指标、故障、扩容案例、政策匹配案例和缺失数据案例。
- 业务表范围：区域、运营商、充电站、连接器、运营指标、故障、候选站点、政策条件、站点评分、扩容方案、导入批次、Agent 运行、工具调用、RAG 文档、RAG Chunk 和审计日志。
- 数据导入入口：模板下载、CSV/JSON/GeoJSON 上传、字段映射、预览、校验、批次导入、失败记录下载和批次回滚。
- 每条数据必须保存 `source_type`、来源 URL或文件、数据版本和 `import_batch_id`。
- `source_type` 只允许：`public`、`user_upload`、`synthetic`、`agent`。

## 前端验收边界

- 每个业务 Agent 必须有独立菜单入口。
- RAG 上传、切块、向量化和检索必须有独立菜单入口。
- 业务数据导入必须有独立菜单入口。
- 菜单切换、路由刷新和权限拦截必须生效。
- 上传、解析、切块、向量化、检索和 Agent 运行必须显示处理中、成功、失败和空数据反馈。
- Agent 页面必须显示业务输入、运行阶段、工具调用、MySQL 数据依据、RAG 证据、结论、风险和人工确认状态。
- 检索结果必须可以打开原文片段抽屉，并显示文档、版本、Chunk ID、相关度和来源。
- ECharts 大屏必须支持地图、趋势、排行、覆盖热力、候选评分和扩容优先级展示。

## MVP 验收标准

- 可以导入一批公开充电站数据，并在 MySQL、站点列表和地图中查询。
- 可以上传候选站点 CSV，并完成字段映射、校验和导入批次查询。
- 可以上传 Markdown 政策文档，查看切块，完成向量化和检索。
- 可以从 5 个独立菜单分别运行 5 个业务 Agent。
- 5 个 Agent 都能查询 MySQL 业务数据并调用 RAG 知识库。
- 5 个 Agent 都能显示可回溯的业务数据证据和 RAG 原文片段。
- 候选选址评分和扩容数量由确定性代码计算，模型只负责解释和组织建议。
- 高影响的扩容或政策结果进入人工确认，不能直接批准。
- 数据不足、RAG 无命中、模型不可用和工具失败都有明确停止状态。
- Windows 本地启动和 Docker Compose 启动作为后续部署步骤验收，不在 Step 1 实施。

## 非目标

- 不实现市政设施报修、巡检、工单、派工和维修验收。
- 不实现论文解析、量规评分、论文一致性审查和修改建议。
- 不直接控制充电桩、支付系统、电网设备或真实施工审批系统。
- 不把合成数据展示为真实运营数据。
- 不把模型生成的建议视为最终投资、消防、电气或政策审批结论。

# chargeops 执行手册

## Step 1：确认项目范围和验收边界

- 固化项目名称、项目目录、技术栈和部署方式。
- 固化 5 个业务 Agent：覆盖缺口、竞争分析、候选选址、站点扩容、政策匹配。
- 固化 RAG 菜单：文档上传、文本切块、向量化入库、向量检索、检索结果和原文展示。
- 固化 MySQL 菜单：模板下载、文件上传、字段映射、数据预览、校验、导入批次和失败记录。
- 固化公开数据、用户上传数据和合成数据的 `source_type` 取值。
- 固化不直接控制真实充电桩、不自动审批建设、不保证真实订单预测的边界。
- 为每个 Agent 编写至少 5 条验收样例的标题和预期结果。
- 将范围、非目标、角色、页面、数据和验收要求记录到需求文档。

## Step 2：创建 Git 仓库和项目目录

- 在 `D:/LEARN/AI/programs/AgentTask/Projects/chargeops` 初始化 Git 仓库。
- 创建 `backend`、`frontend`、`data`、`rag_docs`、`scripts`、`docs`、`infra` 和 `logs` 目录。
- 创建 `data/raw/public`、`data/raw/user_upload`、`data/raw/synthetic`、`data/processed`、`data/manifests` 和 `data/templates`。
- 创建 RAG 文档分类目录：`charging_standards`、`operation_manuals`、`subsidy_policies`、`site_selection`、`business_rules`。
- 创建 `.gitignore`，忽略 `.env`、密钥、数据库文件、Chroma 持久化目录、上传文件、日志和构建产物。
- 创建 `README.md`、`.env.example`、`compose.yaml` 占位文件和版本信息文件。
- 创建 `main` 分支并提交目录骨架。

## Step 3：配置 Windows 本地开发环境

- 检查 Python 3.11+、Node.js 22+、npm、Git 和 Docker Desktop 版本。
- 创建或确认项目使用的 Python 虚拟环境。
- 安装 FastAPI、Uvicorn、SQLAlchemy、PyMySQL、Pydantic、LangChain、LangGraph、Chroma 客户端和 Markdown 解析依赖。
- 安装 Vue 3、TypeScript、Vite、Element Plus、ECharts、Axios、Vue Router 和状态管理依赖。
- 创建后端和前端的锁定依赖文件。
- 复制 `.env.example` 为本地 `.env`，填写数据库、Chroma、模型和认证配置。
- 确认密钥不会写入 Git、测试夹具、日志或 API 响应。

## Step 4：准备 MySQL、Chroma 和模型服务

- 创建 MySQL 数据库和最小权限用户。
- 启动 Chroma Server，确认健康接口可访问。
- 配置 OpenAI-compatible Chat 接口。
- 配置 Embedding 接口和模型名称。
- 可选配置 Rerank 接口；未配置时关闭 Rerank，不伪装为已启用。
- 编写 `/health` 和 `/ready` 所需的依赖检查。
- 记录 MySQL、Chroma、Chat、Embedding 和 Rerank 的连接状态。
- 外部模型不可用时，保留数据导入和 RAG 文档管理功能的可启动状态。

## Step 5：下载并登记公开充电站数据

- 从 [AFDC Data Downloads](https://afdc.energy.gov/data_download) 下载首批充电站数据。
- 保存原始 CSV 或 JSON 到 `data/raw/public`，禁止直接修改原始文件。
- 保存站点、连接器、运营商、经纬度、地址、状态和充电类型字段说明。
- 创建数据来源清单，记录来源 URL、下载时间、文件名、文件大小、行数和 SHA-256。
- 在数据清单中记录公开许可或使用说明。
- 为后续导入确定外部主键、站点主键和连接器主键映射。
- 选择一个区域作为首批演示范围，避免首次导入数据量过大。

## Step 6：准备用户上传模板和合成业务数据

- 为候选站点创建 `candidate_sites_template.csv`。
- 为站点运营指标创建 `station_metrics_template.csv`。
- 为站点故障创建 `station_faults_template.csv`。
- 为扩容案例创建 `expansion_cases_template.csv`。
- 使用固定随机种子生成演示运营指标、故障、候选地址、预算和政策匹配案例。
- 为每条合成记录写入 `source_type=synthetic`、生成器版本、生成时间和批次 ID。
- 生成包含正常、高利用率、低利用率、故障集中、缺失坐标和过期数据的样例。
- 将模板和生成结果写入 `data/templates` 和 `data/raw/synthetic`。

## Step 7：建立公开数据清洗和统一映射

- 建立站点字段到统一模型字段的映射表。
- 清洗站点名称、运营商名称、地址、充电类型和状态枚举。
- 验证经纬度范围，记录无效坐标和缺失坐标。
- 统一日期、时间、时区和生效日期格式。
- 处理外部 ID 重复、站点重复和连接器重复。
- 将充电功率、连接器数量、站点状态转换为统一数据类型。
- 输出到 `data/processed`，不覆盖 `data/raw`。
- 生成字段统计、缺失值、重复值、失败行和清洗批次报告。
- 在处理结果中保留原始 ID、来源 URL、原始文件和导入批次。

## Step 8：设计 MySQL 数据模型

- 创建 `users`、`roles`、`permissions` 和角色权限关联表。
- 创建 `region`、`operator`、`charging_station` 和 `charging_connector`。
- 创建 `station_operation_metric`、`station_fault_event` 和 `candidate_site`。
- 创建 `policy_condition`、`site_score` 和 `expansion_plan`。
- 创建 `import_batch`、`agent_run`、`tool_call`、`rag_document`、`rag_chunk` 和 `audit_log`。
- 为所有业务表增加来源、版本、导入批次、创建时间和更新时间字段。
- 为站点、候选点、区域、Agent 运行和导入批次建立索引。
- 设置外键、唯一约束、软删除字段和状态枚举。
- 明确哪些表允许回滚，哪些审计记录不可变更。
- 输出数据库关系图和字段数据字典。

## Step 9：实现数据库初始化、导入和回滚

- 编写数据库建表或迁移脚本。
- 编写空库初始化脚本。
- 编写站点、连接器、运营商、区域和候选站点导入脚本。
- 编写运营指标、故障和扩容案例导入脚本。
- 所有导入使用 `import_batch_id` 关联。
- 导入前执行文件哈希、字段、枚举、坐标、外键和重复校验。
- 导入失败时记录失败行、字段和原因。
- 支持整批回滚或对失败行修复后重新导入。
- 重复导入同一文件时返回已有批次，不重复插入业务数据。

## Step 10：搭建 FastAPI 应用基础层

- 创建 FastAPI 应用工厂和应用入口。
- 实现配置加载、环境变量校验和敏感配置保护。
- 实现 SQLAlchemy Session、事务边界和依赖注入。
- 实现 CORS、请求 ID、Trace ID 和结构化 JSON 日志。
- 实现统一异常处理和统一错误响应。
- 实现 `/health`、`/ready` 和 `/openapi.json`。
- 在 `/ready` 中分别检查 MySQL、Chroma、Chat 和 Embedding。
- 创建 API 路由、服务层、模型层、Schema 层和工具层目录。
- 为错误响应统一返回 `error_code`、`message`、`trace_id` 和 `retryable`。

## Step 11：实现认证、角色和权限

- 实现登录、Token 签发、Token 校验和当前用户接口。
- 创建运营分析师、选址规划师、运维负责人、政策管理员、系统管理员和审计人员角色。
- 将角色与菜单、API 和 Agent 工具权限关联。
- 在路由层、服务层和 Agent 工具层执行权限校验。
- 限制用户能访问的数据范围和可写入的数据集。
- 对文档删除、向量重建、数据覆盖、扩容方案发布增加人工确认。
- 记录登录成功、Token 失败、权限拒绝和人工确认事件。
- 配置密码哈希、Token 过期时间和认证密钥轮换方式。

## Step 12：实现区域、运营商、站点和连接器模块

- 实现区域列表、层级关系、边界和区域筛选。
- 实现运营商列表、详情和站点关联。
- 实现充电站分页、筛选、详情和来源展示。
- 实现连接器类型、功率、数量和状态查询。
- 实现按经纬度、区域、运营商、充电类型和状态查询站点。
- 实现地图点位接口和点位详情接口。
- 在列表和详情中显示公开、用户上传和合成数据标签。
- 支持从站点详情跳转到运营指标、故障、Agent 运行和相关扩容方案。

## Step 13：实现运营指标、故障和候选站点模块

- 实现站点日/小时运营指标查询。
- 实现充电次数、电量、峰值功率、占用率和平均时长查询。
- 实现故障事件创建、查询、恢复时间和严重等级。
- 实现候选站点创建、编辑、删除和状态管理。
- 实现候选站点经纬度、区域、面积、停车位、电力容量、预算和交通指标保存。
- 实现候选站点与周边站点、区域和政策的关联查询。
- 增加候选站点数据完整度和时效性计算。
- 缺少关键字段时标记为不可评估，不允许直接进入推荐状态。

## Step 14：实现 RAG 文档上传和 Markdown 解析

- 实现 Markdown 文件上传接口和前端上传页面。
- 校验扩展名、文件大小、文件名、内容类型和文件 SHA-256。
- 保存原始文件、文档 ID、文档类型、来源 URL、区域、版本和生效日期。
- 解析标题、段落、列表、表格和条款编号。
- 记录解析中、解析成功、解析失败和待重试状态。
- 对重复文件返回已有文档或要求创建新版本。
- 将原文和元数据写入 MySQL，不在 Chroma 中保存业务状态。
- 为解析失败文档提供错误信息和重试入口。

## Step 15：实现文本清洗和 Chunk 预览

- 清理不可见字符、重复空白、异常换行和无意义页眉页脚。
- 按 Markdown 标题、条款、段落、列表和表格边界切块。
- 设置默认 Chunk 长度 800 tokens、重叠 120 tokens。
- 保存 `chunk_id`、标题层级、Chunk 序号、字符起止位置和文档版本。
- 实现切块预览页面。
- 支持修改目标长度和重叠长度后重新切块。
- 重新切块时保留旧批次，不覆盖历史 Chunk。
- 检查 Chunk 是否为空、是否超长、是否丢失标题和条款编号。
- 支持从 Chunk 跳转到原文片段。

## Step 16：实现 Embedding 和 Chroma 入库

- 实现 OpenAI-compatible Embedding 客户端。
- 实现批量向量化、超时、重试、限流和失败记录。
- 记录 Embedding 模型名称、模型版本、批次 ID 和参数。
- 将 Chunk ID、文档 ID、区域、类型和版本写入 Chroma metadata。
- 实现单文档向量化、批次向量化和文档级重建。
- 向量写入失败时保留待重试状态，不写入不完整向量。
- 支持查询向量化批次、成功数量、失败数量和待重试数量。
- 支持按文档版本删除或重建向量。

## Step 17：实现 RAG 检索和原文片段展示

- 实现查询输入、查询改写和 Agent 场景标签。
- 实现 Chroma 向量召回和 MySQL 关键词召回。
- 实现文档类型、区域、生效日期、版本和 Agent 场景过滤。
- 实现候选合并、去重、相关度排序和可选 Rerank。
- 设置默认 Top-K 为 5，并允许前端调整。
- 将命中 Chunk 回填为原文连续片段。
- 在结果页展示文档标题、版本、来源 URL、Chunk ID、相关度和原文。
- 支持从结果跳转到文档、Chunk 和原始 Markdown。
- 没有命中或命中证据不足时显示明确状态。
- 记录每次检索的查询、过滤条件、命中结果和运行 ID。

## Step 18：设计 Agent 状态和工具契约

- 定义 LangGraph 状态：用户输入、业务范围、数据版本、检索查询、证据、工具结果、计算结果、结论、错误和停止原因。
- 为 5 个 Agent 分别定义输入 Schema、输出 Schema 和错误 Schema。
- 登记 MySQL 查询工具、确定性计算工具、RAG 检索工具和结果写入工具。
- 为每个工具定义参数、返回值、权限、风险等级、幂等规则和可重试错误。
- 定义证据结构，保存文档 ID、Chunk ID、原文片段和来源 URL。
- 定义 `EVIDENCE_INSUFFICIENT`、`MISSING_BUSINESS_DATA`、`STALE_DATA`、`WAITING_CONFIRMATION` 等停止原因。
- 定义 Agent 运行、工具调用、模型调用和人工确认记录结构。

## Step 19：实现 Agent 工具执行层

- 实现站点、区域、运营商、连接器和候选站点查询工具。
- 实现运营指标、故障、竞争范围和邻近站点查询工具。
- 实现距离、覆盖率、竞争指数、候选点评分和政策匹配计算工具。
- 实现 RAG 检索、原文回填和证据校验工具。
- 实现评分、扩容方案、覆盖分析、竞争分析和政策结果保存工具。
- 工具执行前校验参数、用户权限、数据范围、数据版本和风险等级。
- 工具执行后记录输入摘要、输出摘要、耗时、错误和审计事件。
- 重复写入使用幂等键，重复请求返回原结果。

## Step 20：实现 Supervisor 和 LangGraph 循环控制

- 创建 Supervisor，按用户选择路由到 5 个业务 Agent。
- 让每个 Agent 独立完成“读取业务数据 → RAG 检索 → 计算 → 业务解释 → 结果保存”。
- 限制单次运行模型调用、工具调用、总耗时和循环次数。
- 实现证据不足、数据不足、模型错误、工具错误、超时和连续无进展停止。
- 高影响结果进入 `WAITING_CONFIRMATION`，等待用户确认或拒绝。
- 保存状态快照，支持查看运行轨迹、取消和重试。
- 将模型、工具、RAG、计算和人工确认事件写入 `agent_run` 和 `tool_call`。

## Step 21：实现覆盖缺口 Agent

- 编写覆盖缺口 Agent 的系统 Prompt、输入 Schema 和输出 Schema。
- 实现区域边界、站点和连接器查询。
- 实现站点密度、快充比例、最近站点距离和覆盖半径计算。
- 通过 RAG 检索覆盖标准、建设规范和区域政策。
- 输出空间缺口、快充缺口、时段缺口和数据不足分类。
- 保存覆盖分析结果、数据版本和原文证据。
- 对无区域边界、无有效坐标、数据过期和无 RAG 命中场景停止运行。
- 在覆盖缺口菜单展示输入、运行步骤、指标、结论和原文片段。

## Step 22：实现竞争分析 Agent

- 编写竞争分析 Agent 的系统 Prompt、输入 Schema 和输出 Schema。
- 实现按坐标和半径查询周边站点。
- 实现按运营商、充电类型、连接器数量和功率分组。
- 实现距离权重、运营商集中度和竞争强度计算。
- 通过 RAG 检索运营商评价规则、差异化建设规则和服务要求。
- 输出周边竞争站点、运营商分布、服务空白和竞争风险。
- 保存竞争分析结果及使用的站点数据版本。
- 在竞争格局菜单展示地图、表格、图表和原文证据。

## Step 23：实现候选选址 Agent

- 编写候选选址 Agent 的系统 Prompt、输入 Schema 和输出 Schema。
- 实现候选站点、区域、周边站点、交通指标和建设条件查询。
- 实现覆盖缺口、交通和人口、竞争、建设条件、政策适配和数据可信度评分。
- 将评分权重保存为可版本化配置，不把权重写死在 Prompt 中。
- 使用确定性代码完成总分、等级和排序计算。
- 通过 RAG 检索选址规则、建设要求和审批条件。
- 输出总分、分项得分、扣分原因、缺失数据、政策证据和推荐动作。
- 缺失关键数据时降低数据可信度，不自动生成高等级推荐。
- 在候选选址菜单展示雷达图、评分明细、证据抽屉和报告导出。

## Step 24：实现站点扩容 Agent

- 编写站点扩容 Agent 的系统 Prompt、输入 Schema 和输出 Schema。
- 实现站点运营指标、连接器占用率、故障记录和现有功率查询。
- 计算高峰占用、低效连接器、故障集中度和潜在扩容需求。
- 通过 RAG 检索扩容、设备安全、并网和运维规则。
- 生成新增快充数量、新增慢充数量、功率调整和优先级建议。
- 保存扩容方案、预算区间、前置条件、风险和证据。
- 对缺少运营指标、故障记录或电力容量的数据标记待补充。
- 在站点扩容菜单展示站点详情、趋势、扩容前后对比和人工确认入口。

## Step 25：实现政策与补贴匹配 Agent

- 编写政策匹配 Agent 的系统 Prompt、输入 Schema 和输出 Schema。
- 按区域、站点类型、运营主体和生效日期筛选政策。
- 从 MySQL 读取候选站点字段和建设条件。
- 从 Chroma 检索政策资格、材料、金额、截止日期和限制条件。
- 实现政策条件逐项匹配，区分通过、部分通过、不通过和无法判断。
- 输出缺失字段、缺少材料、政策版本、截止日期和原文片段。
- 保存政策匹配结果和运行版本。
- 在政策与补贴菜单展示条件矩阵、材料清单、时间线和原文证据。

## Step 26：实现决策报告和人工确认

- 创建覆盖分析、竞争分析、选址评分、扩容方案和政策匹配报告模型。
- 将每份报告关联 `run_id`、数据批次、文档版本、计算规则版本和模型版本。
- 实现报告草稿、待确认、已批准、已拒绝和归档状态。
- 提供统一的报告详情页，展示结论、计算指标、MySQL 数据和 RAG 证据。
